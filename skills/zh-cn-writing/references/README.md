# 简体中文写作规范

本规范适用于以简体中文撰写的技术文档、README、代码注释和 Commit Message。

本规范在 [ruanyf/document-style-guide](https://github.com/ruanyf/document-style-guide) 的基础上修订，并参考了文末列出的资料。

## 设计目标

- 易读、易写、易修改。
- 文件差异对比友好。
- 表达精准，没有歧义。
- 规则能由工具检查的，交给工具检查。

文档统一使用 Markdown 编写，语法以 [CommonMark](https://commonmark.org/) 与 [GitHub Flavored Markdown](https://github.github.com/gfm/) 为准。

## 工具检查

格式类规则由工具检查，正文只说明工具判断不了的部分。

| 工具 | 负责的规则 | 配置文件 |
| --- | --- | --- |
| [AutoCorrect](https://github.com/huacnlee/autocorrect) | 中英文间距、全角与半角标点、专有名词拼写 | [`.autocorrectrc`](../assets/.autocorrectrc) |
| [markdownlint](https://github.com/DavidAnson/markdownlint) | 标题层级、空行、列表与代码块格式 | [`.markdownlint.jsonc`](../assets/.markdownlint.jsonc) |

工具与本规范冲突时，以本规范为准，并同步修改工具配置。

## 标题

### 层级

标题最多使用四级：

- 一级标题：文档标题，每篇文档只有一个。
- 二级标题：文档主要部分的标题。
- 三级标题：二级标题下的小节。
- 四级标题：三级标题下某一方面的小节。

如果文档框架通过 frontmatter 的 `title` 字段生成文档标题（例如 Fumadocs、VitePress），正文不再写一级标题，直接从二级标题开始。

### 原则

- 章节标题从二级标题开始，一级标题下不能直接出现三级标题。
- 所有标题前后都留一个空行。
- 同级标题至少有两个，避免孤立的单个子标题。
- 下级标题不重复上级标题的名称。
- 标题末尾不使用句号、逗号、顿号、分号和冒号；问号和叹号可以使用。
- 层级保持简单。超过四级时，应考虑拆分文档。

## 间距

中文与英文、中文与数字之间加一个半角空格：

> 正确：使用 Bun 1.2 构建，耗时 3 秒。
>
> 错误：使用Bun1.2构建，耗时3秒。

数字与单位之间加一个半角空格，但度数、百分号不加：

> 正确：文件大小为 5 MB，压缩率 30%，夹角 90°。

全角标点与相邻的任何字符之间都不加空格：

> 正确：安装完成后，运行 `bun test`。
>
> 错误：安装完成后 ，运行 `bun test` 。

行内代码、链接与中文之间加一个半角空格；与全角标点之间不加空格。

英文句子内部遵循英文排版习惯：半角逗号、句号、冒号后面加一个空格，前面不加。

## 句子

### 长度

每个句子只表达一个意思。以两个标点之间的字数计算：

- 20 个字以内：最佳。
- 20～29 个字：可以接受。
- 30～39 个字：语义必须明确才能接受。
- 40 个字以上：拆分成多个句子。

### 句式

- 优先使用简单句和并列句，避免多层嵌套的复合句。
- 优先使用肯定句。「保留原文件」比「不要删除原文件」更容易理解。
- 优先使用主动语态。「`build` 命令清空 `dist` 目录」比「`dist` 目录会被 `build` 命令清空」更直接。
- 使用代词（如「其」「该」「此」「这」）时，必须只有一个可能的指代对象；否则直接写出名称。
- 正确使用「的」「地」「得」。

### 语气

- 使用陈述语气，避免感叹语气和口语化表达。
- 不使用营销用语，如「强大的」「极致的」「一站式」。用具体的行为、数字或限制代替。

## 段落

- 一个段落只有一个主题。
- 段落的中心句放在段首，后续句子为中心句服务。
- 段落长度不超过七行，最好在四行以内。
- 段落之间用一个空行分隔，段首不留空白字符。

## 列表

- 列表项是完整句子时，以句号结尾；是词语或短语时，不加标点。
- 同一个列表内的各项结构保持一致，要么都是句子，要么都是短语。
- 引出列表的句子以冒号结尾。

## 术语与缩写

- 术语首次出现时给出定义，之后保持同一个叫法，不混用同义词。
- 缩写首次出现时，在括号中给出全称，例如「抽象语法树（Abstract Syntax Tree，AST）」。之后直接使用缩写。
- 专有名词按官方写法书写，不论是否位于句首，见 [专有名词](#专有名词)。
- 普通英文单词不需要首字母大写。

## 技术文档中的中英混排

- 代码标识符（函数名、变量名、类型名、命令、文件路径、配置项）保持英文原文，用行内代码包裹，例如 `useState`、`package.json`。
- API 名称和代码标识符不翻译，也不加中文复数或量词后缀。
- 已有通行中文译名的概念使用中文，例如「中间件」「类型守卫」「依赖」；没有通行译名的保持英文，例如 Hook、Tree-shaking。
- 同一个概念在全文中只用一种写法，不要中英文交替出现。
- 代码块必须标注语言类型，例如 `ts`、`bash`。
- 不使用包含大量文字的截图；需要展示的文字直接写成文本或代码块。

## 数字

- 阿拉伯数字一律使用半角形式。
- 四位以上的整数使用半角逗号作为千位分隔符，例如 `12,345`。年份、编号、版本号和代码中的数字除外。
- 数值范围用全角波浪线「～」连接，两端都写单位或百分号，例如「10%～20%」「3 天～5 天」。也可以用汉字「至」代替。
- 货币金额使用阿拉伯数字，在数字前写货币符号或在数字后写中文名称，例如「¥100」「100 元」。英文货币代码参考 ISO 4217。

## 标点符号

### 通用规则

- 中文句子使用全角标点；整句都是英文时，使用半角标点。
- 数字内部使用半角符号，例如小数点、时间中的冒号「12:30」。
- 句号、问号、叹号、逗号、顿号、分号和冒号不能出现在行首。

### 句号

- 中文句子末尾使用全角句号「。」。
- 句末用括号补充说明时，句号放在括号之外，例如「运行测试（需要先安装 Playwright）。」。整句都在括号内时，句号放在括号之内。

### 逗号与顿号

- 逗号「，」表示句子内部的一般停顿。避免整个段落只用逗号断句。
- 并列的词语之间使用顿号「、」，即使并列的是英文词，例如「支持 Chromium、WebKit 和 Firefox」。
- 中文句子中并列的最后一项，优先用「和」「或」连接。

### 分号与冒号

- 分号「；」用于复句内部并列分句之间的停顿。
- 冒号「：」用于引出解释、说明或列表。

### 引号

- 中文使用直角引号。外层用「」，内层用『』，例如：「请先阅读『设计目标』一节」。
- 英文句子使用半角直引号 `"` 和 `'`。
- 不使用弯引号 “” 和 ‘’。选择直角引号的原因见 [常见问题](#为什么使用直角引号)。

### 括号

- 中文句子中的补充说明使用全角圆括号「（）」，括号前后不加空格。
- 括号内全部是英文时，使用半角括号，括号外侧与中文之间加一个空格。

常见括号的中英文名称：

| 符号 | 英文 | 中文 |
| --- | --- | --- |
| `( )` | parentheses | 圆括号 |
| `[ ]` | square brackets | 方括号 |
| `{ }` | curly brackets 或 braces | 花括号 |
| `< >` | angle brackets | 尖括号 |

### 省略号与连接号

- 省略号使用「……」（两个 U+2026），不使用「。。。」或「...」。
- 连接两个名词构成复合词，或表示编号时，使用半角连字符「-」，例如「氧化-还原反应」「图 1-1」。
- 数值范围使用全角波浪线「～」，见 [数字](#数字)。

## 引用

- 引用第三方内容时使用 `>` 块引用，并注明出处。
- 全文转载或翻译时，在文首显著位置注明作者和出处，并链接到原文。
- 使用外部图片时，在图片下方或文末注明来源。
- 链接使用 Markdown 链接语法，不直接粘贴裸 URL。

## 用词

### 人称

- 文档、README、博客等面向不特定读者的场合，使用「你」。
- 邀请函等指向特定个人的正式场合，使用「您」。
- 同一篇文档中不要混用「你」和「您」。

### 专有名词

专有名词按官方写法书写，不论是否位于句首。

| 正确 | 错误 |
| --- | --- |
| App、应用 | APP、app（句首除外） |
| Android | android、安卓 |
| iOS | ios、IOS |
| iPhone | iphone、IPHONE |
| App Store | AppStore、app store |
| Wi-Fi | WiFi、wifi、Wifi |
| email | E-mail、Email（句首除外） |
| GitHub | Github、github |
| JavaScript | Javascript、JS（正式文档中） |
| TypeScript | Typescript、TS（正式文档中） |
| Node.js | NodeJS、nodejs、Node |
| CSS、HTML、URL、API | css、html、url、api |
| LaTeX | Latex、LaTex |

App 是 application 的缩写，按单词读作 /æp/，不是首字母缩写，所以不写成全大写的 APP。多数情况下可以直接使用中文「应用」。

### 易混淆词

| 正确用法 | 说明 |
| --- | --- |
| 登录 | 进入系统或账号。「登陆」指登上陆地，不用于软件场景。 |
| 账号 | 用于登录的标识，例如用户名、邮箱。 |
| 账户 | 资金、资源或权限的归属主体，例如银行账户、云服务账户。 |
| 其他 | 「其它」是旧写法，统一使用「其他」。 |

## 常见问题

### 为什么使用直角引号

1. 弯引号 “” 和 ‘’ 与英文共用 Unicode 码位，显示成全角还是半角取决于字体，同一份文档在不同环境下的显示效果不一致。直角引号「」『』只用于中日韩文字，不存在这个问题。
2. 直角引号在屏幕上的辨识度更高，与英文的半角直引号 `"` 也不会混淆。

引号的码位对照：

| 名称 | 符号 | Unicode |
| --- | --- | --- |
| 半角直双引号 | `"` | U+0022 |
| 半角直单引号 | `'` | U+0027 |
| 左右弯双引号 | “ ” | U+201C、U+201D |
| 左右弯单引号 | ‘ ’ | U+2018、U+2019 |
| 直角单引号（横排） | 「 」 | U+300C、U+300D |
| 直角双引号（横排） | 『 』 | U+300E、U+300F |

### 为什么中文与数字之间也加空格

原规范允许加或不加，只要求全文统一。为了让 AutoCorrect 能自动检查，本规范统一为加空格。
