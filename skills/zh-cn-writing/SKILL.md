# 简体中文写作规范

撰写或修改简体中文内容时遵循以下规则。完整说明与理由见 [references/README.md](references/README.md)。

## 工作方式

1. 写作时直接遵循下列规则。
2. 写完后，如果本机可以运行 AutoCorrect，对改动的文件执行检查并修复格式问题：
   `npx autocorrect-node --fix --config <本目录>/assets/.autocorrectrc <文件>`
3. 改动 Markdown 文件时，如果本机可以运行 markdownlint，使用 `<本目录>/assets/.markdownlint.jsonc` 检查格式。
4. 只修改本次任务涉及的内容，不顺手重排整篇文档的格式。

## 间距

- 中文与英文、中文与数字之间加一个半角空格：`使用 Bun 1.2 构建`。
- 中文与行内代码、链接之间加一个半角空格：``运行 `bun test` 即可``。
- 全角标点与任何字符之间都不加空格：``完成后，运行 `bun test`。``
- 数字与单位之间加空格（`5 MB`），百分号和度数除外（`30%`、`90°`）。

## 标点

- 中文句子使用全角标点；整句为英文时使用半角标点。
- 并列词语用顿号：`支持 Chromium、WebKit 和 Firefox`。
- 引号使用直角引号，外层「」，内层『』。不使用 “” 和 ‘’。
- 补充说明使用全角括号（）；括号内全为英文时使用半角括号。
- 句末括号注释时，句号放在括号外：`运行测试（需要先安装 Playwright）。`
- 省略号写作「……」；数值范围用全角「～」，两端都带单位：`3 天～5 天`。
- 数字内部使用半角符号：`12:30`、`3.14`。

## 标题

- 一级标题是文档标题，每篇一个；框架通过 frontmatter `title` 生成标题时，正文从二级标题开始。
- 不跳级，标题前后留空行，同级标题至少两个。
- 标题末尾不加句号、逗号、顿号、分号、冒号。

## 句子与段落

- 一句话只表达一个意思；两个标点之间超过 40 字时拆分。
- 优先使用肯定句和主动语态。
- 代词必须只有一个可能的指代对象，否则直接写名称。
- 一个段落一个主题，中心句放在段首，段落不超过七行。
- 使用陈述语气。不用感叹语气、口语和营销词（「强大的」「极致的」「一站式」），改用具体的行为、数字或限制。

## 列表

- 列表项是完整句子时以句号结尾，是短语时不加标点；同一列表结构一致。
- 引出列表的句子以冒号结尾。

## 术语与代码

- 术语首次出现时给出定义，之后全文使用同一个叫法。
- 缩写首次出现时括号注明全称：`抽象语法树（Abstract Syntax Tree，AST）`。
- 代码标识符、命令、路径、配置项保持英文并用行内代码包裹，不翻译。
- 有通行中文译名的概念用中文（中间件、类型守卫），没有的保持英文（Hook、Tree-shaking）。
- 代码块必须标注语言。
- 链接使用 Markdown 语法，不粘贴裸 URL。

## 用词

- 面向不特定读者使用「你」，全文不与「您」混用。
- 使用「登录」，不用「登陆」；使用「其他」，不用「其它」。
- 「账号」指登录标识，「账户」指资金或资源的归属，按语义区分。
- 专有名词按官方写法：App、Android、iOS、iPhone、App Store、Wi-Fi、GitHub、JavaScript、TypeScript、Node.js、CSS、HTML、URL、API、LaTeX。

## 示例

错误：

```markdown
## 安装：
使用bun安装依赖后,运行"bun test"即可.该命令会被CI调用,非常强大!
```

正确：

```markdown
## 安装

使用 Bun 安装依赖后，运行 `bun test`。CI 也调用这条命令。
```
